# Personal Content Intelligence Pipeline

A self-hosted data platform that turns personal movie, TV, and book history into weekly recommendations and a natural-language Q&A assistant. No paid APIs and no cloud LLM: everything runs locally.

## What it does

Streaming and tracking platforms each see only their own slice of viewing and reading history, so their recommendations and stats stay siloed. This project pulls that history together from Simkl (movies and TV) and Hardcover (books), builds one taste profile across all three, and serves two features from a small Flask app:

1. **Picks:** 10 scored and validated movie/TV picks, balanced across language and content type instead of raw global popularity, plus 5 book picks. Refreshed every Friday.
2. **Ask:** a plain-English question box ("highest-rated genre?", "Hindi movies not seen yet?") that runs real SQL against the warehouse and answers only from the rows it returns.

A status page shows pipeline health, and Metabase serves the same warehouse as a BI dashboard. Neither AI feature depends on an external LLM API or a subscription; both run on local Ollama models sized for consumer hardware.

## Architecture

```text
SOURCES → INGESTION (Dagster) → TRANSFORM (dbt) → META (Dagster)
   → AI LAYER (Ollama) → SERVING (Flask/Metabase)
   orchestrated end-to-end by Dagster on a schedule
```

Four APIs (TMDB, Simkl, Hardcover, OpenLibrary) land in Postgres `raw` tables via Dagster ops. dbt turns those into typed staging views, then a dimensional `marts` schema (conformed dimensions, bridge tables, fact tables) that is tested and indexed. Two more Dagster ops compute a taste profile and the weekly picks from the marts into a `meta` schema. Flask and Metabase read from there.

Full diagram and service list: [`docs/architecture.md`](docs/architecture.md).

## Tech stack

| Layer | Tool | Why chosen |
| --- | --- | --- |
| Ingestion | Python + Dagster ops, Pydantic validation | Typed validation per source before anything touches the DB; Dagster gives each source its own retriable, observable unit |
| Transform | dbt (dbt-core + dbt-postgres) | SQL-native, testable, version-controlled transformations; separates what the source sent from what was computed |
| Orchestration | Dagster (webserver + daemon + code server) | Real data-dependency graphs between ops, not task ordering alone; schedules, sensors, run history, and logs in one place |
| AI | Ollama (`llama3.2:1b` picks, `llama3.2:3b` /ask) + LangChain | Free local inference with no internet dependency; LangChain's `SQLDatabase`/`ChatOllama` wrap the text-to-SQL loop |
| Serving | Flask, Metabase | Flask: small surface area (6 routes) with no framework overhead for a single-user app. Metabase: ad-hoc BI over the same marts |
| Infrastructure | Docker Compose, Postgres 15 | 8 services in one `docker-compose.yml`, one Postgres for all pipeline data, and every image and pip package pinned, so it reproduces on any machine with Docker |

## How the AI features work

**Picks** are not generated by an LLM. They are scored with plain math (genre-match average plus creator-match average against real rating history) and filtered by candidate-quality rules: unwatched, not dismissed, enough votes, available on a streaming platform in the configured region, and never a daily soap, TV serial, reality, or talk format (flagged once in `dim_watchable.is_serial_format` from episodes per season and vote count). Ollama's `llama3.2:1b` only chooses which 10 of the top-scored candidates to feature and in what order. Every id it returns is checked against the real shortlist before it reaches the database, and a fully deterministic fallback selects picks if the model is unreachable or misbehaves. A rules pass afterwards enforces the two things the small model doesn't reliably do on its own: per-language slot targets and a minimum share of movies.

**Ask** is open-ended natural language rather than a closed selection. `llama3.2:3b` generates SQL from the question, deterministic checks repair known model mistakes (missing joins, dropped filters, missing minimum-count floors on averages), and the query runs on a read-only Postgres role with a 5-second statement timeout. Up to two attempts are tried, and the answer is written strictly from the returned rows, never from the model's general knowledge. Questions with no recognisable content keyword are rejected before any SQL is generated.

Both follow the same idea: a small local model is useful, but not reliable enough to trust unchecked, so every output is verified (against the shortlist, or by actually executing it) before it is used.

## Data quality and reliability

- **Validation at the edge:** every API record is parsed into a Pydantic model before insert; malformed records are logged and skipped.
- **Idempotent loads:** all raw writes are `INSERT ... ON CONFLICT` upserts, and every raw row carries the `pipeline_run_id` of the Dagster run that wrote it.
- **Safe deletes:** Simkl delete reconciliation is skipped for any content type that came back empty or had validation failures, so an empty API response can never wipe history.
- **Row-count guards:** an ingestion op raises when a source returns zero rows and warns below an expected minimum.
- **67 dbt tests** (unique, not null, accepted values, foreign-key relationships, composite keys, rating ranges) run after every `dbt run`. A failure stops the run before the taste profile or picks are rebuilt.
- **Source freshness:** dbt warns when raw data is older than 8 days and errors after 15, sized for the weekly cadence.
- **Failure alerts:** a Dagster run-failure sensor records every failed run in `meta.pipeline_alerts` and sends an email; `/health` turns red while the latest failure is newer than the last successful picks.
- **Backups:** a sidecar container runs `pg_dump` daily and keeps the last 14 dumps.

## Quick start

Prerequisites: Docker Desktop, and about 4GB of free RAM for the two Ollama models (plus headroom for Postgres and Metabase).

```bash
git clone https://github.com/surbhi-bhor/content-intelligence.git
cd content-intelligence
cp .env.example .env        # fill in the values listed under Configuration
docker compose up -d --build
docker compose exec dagster-code python init_db.py      # schemas, tables, read-only role, default settings
docker compose exec -w /opt/dbt dagster-code dbt deps   # installs dbt_utils
docker compose exec ollama ollama pull llama3.2:1b      # picks model
docker compose exec ollama ollama pull llama3.2:3b      # /ask model
```

Then open `localhost:3000` (the Dagster UI) and launch `full_ingestion_job` once to load the initial data. After that, the weekly schedule takes over (see Operations).

| Service | URL |
| --- | --- |
| Picks app and `/ask` | `localhost:5000` |
| Dagster UI | `localhost:3000` |
| Metabase | `localhost:4000` (first visit asks for an admin account and a database connection: host `postgres`, port `5432`, database = the `POSTGRES_DB` value) |

## Configuration

**Environment variables** (`.env`, see `.env.example` for the full file):

| Variable | Purpose |
| --- | --- |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | Local Postgres credentials. Any values work; they only bootstrap the container |
| `TMDB_API_KEY` | Free key from themoviedb.org, for movie/TV discovery and enrichment |
| `SIMKL_CLIENT_ID` / `SIMKL_CLIENT_SECRET` / `SIMKL_ACCESS_TOKEN` | Free app at simkl.com, for watch history and ratings. The secret is only needed once, during the OAuth exchange that produces the access token |
| `HARDCOVER_API_TOKEN` | Free key from hardcover.app, for reading history and ratings |
| `ASK_READONLY_PASSWORD` | Password for the read-only Postgres role that `/ask` queries run as. Any value; `init_db.py` creates the role with it |
| `ASK_DATABASE_URL` | Connection string for that role. The default works once `your_ask_readonly_password` in it is replaced with the `ASK_READONLY_PASSWORD` value |
| `OLLAMA_BASE_URL`, `OLLAMA_PICKS_MODEL`, `OLLAMA_ASK_MODEL` | Defaults work for the Docker Compose setup |
| `ALERT_EMAIL_TO`, `SMTP_*` (optional) | Email for failed-run alerts. Gmail requires an App Password. Leave blank to skip email |

**Recommendation settings** live in the `meta.user_config` table (seeded by `init_db.py`, editable with plain SQL):

| Key | Default | Purpose |
| --- | --- | --- |
| `preferred_languages` | `["en", "hi", "mr"]` | Languages discovered from TMDB and eligible for picks |
| `recommendation_language_slots` | `{"en": 4, "hi": 4, "mr": 2}` | How many of the 10 picks go to each language |
| `recommendation_fallback_language` | `"hi"` | Language used to fill a slot when its own language runs out of candidates |
| `watch_region` | `"IN"` | Country (ISO code) used for TMDB streaming availability |
| `excluded_genres` | not set | Optional list of genres never recommended, e.g. `["Animation"]` |

Example: `UPDATE meta.user_config SET config_value = '"US"' WHERE config_key = 'watch_region';`. Title details older than 30 days are re-fetched on each run, so a region change reaches existing titles within a month and new titles straight away.

## Operations

- **Schedule:** `weekly_pipeline_schedule` runs `full_ingestion_job` every Friday at 12:00 IST (`0 12 * * 5`, `Asia/Kolkata`). It ships enabled. Weekly is enough because viewing and reading history doesn't change fast enough to justify a nightly refresh.
- **Health:** `localhost:5000/health` shows the last run, current pick count, last failed run, and row counts for the key tables.
- **Backups:** dumps land in `./backups/postgres` (custom format). Restore with:
  ```bash
  docker compose exec -T postgres sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists' < backups/postgres/<file>.dump
  ```
- **Tests on demand:** `docker compose exec -w /opt/dbt dagster-code dbt build` rebuilds every model and runs all tests.

## Project structure

```text
dagster/            Orchestration: 9 jobs, 14 ops, schema bootstrap (init_db.py)
  ops/               tmdb_op, simkl_op, hardcover_op, openlib_op,
                      taste_profile_op, recommendation_op
  sensors.py         Run-failure alert (email + meta.pipeline_alerts)
dbt/
  models/staging/    5 typed views over raw sources
  models/marts/      10 dimensional tables (dims, bridges, facts)
flask/               The web app: picks page, /ask, /not-interested, /health, /usage
  templates/          base, index (picks + ask bar), health
docs/                Architecture diagram, case study
docker-compose.yml   All 8 services
backups/             Daily pg_dump files (created at runtime, gitignored)
```

## Limitations

- **Single machine:** all data is in one Postgres instance, and the daily backups sit on the same host.
- **No CI:** dbt tests run inside every pipeline run, but nothing runs automatically on a push.
- **No Python test suite or AI eval set:** the dbt layer is tested, while `/ask` and recommendation quality are checked by hand.
- **No authentication:** Flask, Dagster, and Metabase are open on their ports. Fine for localhost, not for shared access.
- **CPU-bound `/ask`:** answers take roughly 40 seconds to a few minutes on a laptop CPU.
- **TMDB connectivity:** some networks intermittently drop TMDB connections. Failed titles keep their previous data and are retried on the next run.
